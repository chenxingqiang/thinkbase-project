are generated from the repository state whose build produces the submitted PDF;
the commit hash is recorded below at submission time.

  `docs/AgentISA.pdf` (run `git rev-parse HEAD` in the artifact root; the
  submission snapshot is the parent of any post-camera fix).

### Components shipped since the original disclosure, with residuals

Two entries formerly listed here are now implemented and benchmarked
(Appendix I.2); residuals that still hold are kept disclosed:

- Capability metric extraction (§3.5) — the seventeen `_measure_*` functions
  in `capability.py` are now implemented as structural measurements over the
  formal instruction records (declared outputs, dependencies, error contracts,
  security flags, …), calibrated in `capability_calibration_results.json`.
  Residual: the measures are structural proxies, not behavioral evaluations —
  on the base instruction pools 9 of 17 metrics remain N/A (no variance), and
  the paper reports exactly that.
- Tree-pattern dynamic-programming instruction selection (§4.1.1) — shipped
  as `InstructionSelector(selection_strategy='dp')` in
  `instruction_selector.py`, benchmarked in `selector_dp_results.json`.
  Residual: the DP optimizes the recorded cost model over the tiling lattice;
  it does not re-plan at runtime.

### Specified-only components (not implemented)

These are design specifications in the paper, **not** shipped mechanisms:

- Symbolic-execution equivalence checker (§4.3.1) — no module; obligations
  argued per-pass in Appendix C instead.
- Cycle-accurate pipeline scheduler (§4.1.2) — the shipped schedule loop is
  sequential execution plus parallel grouping.
- Fusion-node executable composite codegen (§4.1.3 / C.2) — the shipped
  fusion emits formal fusion nodes; the recorded body executes constituents.
  (The *replay* path is differential-tested; a single fused executable
  body distinct from replay remains specified.)

### Disclosed mechanism limitations that still hold

These shipped mechanisms carry caveats the paper keeps disclosing:

- EMA hot-path detector: opt-in `detection_mode="ema"`; remains
  exact-path-keyed (no similarity merging), and the share denominator is the
  LRU-tracked set, so a tail of one-shot paths can floor it until the cap
  evicts them (scenario evidence in `hotpath_ema_results.json`).
- Memory plan (`buffer_reuse_potential`): advisory only — the runtime
  executes the recorded body; reuse is computed, not applied.
- AGGRESSIVE optimization level: structurally identical to ADVANCED except
  for the memory plan (deltas exactly 0.0 in `fusion_chain_results.json`).

### Benchmark arms added for the revision

- `paired_ablation` experiment: same seeds and sequences as the static
  compiler run (seed base 2,000), per-pass decomposition of the 34.2%
  headline; the paired interaction term is reported per seed.
- Cache experiment third arm: naive app-level exact-response cache
  (plain dict on the request payload) — parity finding, Section 5.2.
- Dynamic experiment replay verification: optimized traces re-executed,
  final-state identity recorded per seed (`replay_state_identical`),
  all seeds identical.
- Appendix-I offline extension benches (§5.10–5.11 / I.1–I.2, commands in
  the table above): real-trace census, capability calibration, DP-vs-
  heuristic selector, EMA hot-path stress, strict-security posture matrix,
  cache-key namespacing, parameterized-replay generalization, chain-enriched
  fusion ladder with a random-slots control arm (the control reproduces the
  published §5.3 compiler numbers bit-for-bit at L1000), and the priced
  token-mix sweep with an ordering-invariance check.

## Reproducing the Appendix I.3 live-gateway runs

Two live runs back the gateway-quality and multi-seed sections; both target
the gateway at `https://127.0.0.1:8443` (model `claude-glm-5.3-flash`,
temperature 0) and are the only non-deterministic commands in this file
(live model replies; the *aggregates and analysis* are recomputed from the
recorded raw replies and are fully reproducible offline).

Quality re-run (`gateway_quality_results.json`) — one probe call at the
4096-token ceiling first, then the tiny-scale run:

```bash
python examples/paper_real_llm_quality_check.py --backend real --scale tiny \
    --tasks 1 --max-tokens 4096 --json examples/benchmarks/gateway_quality_probe.json
python examples/paper_real_llm_quality_check.py --backend real --scale tiny \
    --max-tokens 3072 --json examples/benchmarks/gateway_quality_run_raw.json
python examples/benchmarks/e10_gateway_postprocess.py \
    --quality-probe examples/benchmarks/gateway_quality_probe.json \
    --quality-run examples/benchmarks/gateway_quality_run_raw.json \
    --i9-baseline examples/paper_real_llm_quality_results_real.json \
    --multiseed-run examples/benchmarks/gateway_multiseed_raw_zipf0.5.json \
                    examples/benchmarks/gateway_multiseed_raw_zipf1.0.json \
                    examples/benchmarks/gateway_multiseed_raw_zipf1.5.json \

    --quality-out examples/benchmarks/gateway_quality_results.json \
    --multiseed-out examples/benchmarks/gateway_multiseed_results.json
```

Notes, all recorded in the results JSONs' provenance:

- Scale: the "tiny" preset (22 distinct batches, identical batch set to the
  I9 1500-token real run) with `max_tokens` raised to 3072 — chosen by the
  probe-then-scale rule (probe call 15.25 s / 719 completion tokens →
  37.6 tokens/s worst observed throughput → 81.6 s worst-case ceiling
  call, 29 affordable calls; tiny fits the 40-minute budget worst-case at
  29.9 min, the 36-batch paper preset does not at 49.0 min).
- The reported `all_pass` = False is solely the 4/22 replies-bound-at-
  ceiling gate; every agreement statistic recomputes from the raw replies.

Multi-seed cache run (`gateway_multiseed_results.json`):

```bash
python examples/benchmarks/isa_real_llm_bench.py --backend gateway \
    --tasks 100 --seeds 2 --zipf 0.5 --max-tokens 64 \
    --output examples/benchmarks/gateway_multiseed_raw_zipf0.5.json
# one invocation per zipf (repeat with --zipf 1.0 / 1.5 and matching
# --output); --backend gateway is required, the CLI default is the mock
```

- Seed convention `random.Random(1000 + seed)`; the measured hit rates
  match the analytic expectations in all 6 of 6 cells.
- Reduced scale, disclosed in the paper: 100 tasks × 2 seeds per skew
  (vs the frozen 200 × 1 paper run, whose hit rates 8.5% / 26.0% / 45.5%
  are cross-checked in `vs_frozen_paper_run`); the ~2,760-call 5-seed
  extension of this run (1,103 recorded calls over six cells × 15/6) was
  unaffordable under the account quota.
- Quota episode, on record: the first single-invocation attempt crashed
  after ~125 successful calls with a gateway 429 `AccountQuotaExceeded`
  (5-hour quota; reset 21:19:19 +0800). The bench does not retry 429s and
  writes no output on crash; the rerun was chunked per zipf with an outer
  retry wrapper, each chunk a full unmodified bench CLI invocation at the
  sanctioned scale.
- Total: 1,103 gateway calls, wall 3,243.8 s; aggregates recomputed from
  the per-seed cells in the postprocess step.

python examples/paper_real_llm_quality_check.py --backend real --scale paper     --model claude-deepseek-v4-flash     --json examples/benchmarks/gateway_quality_deepseek.json

- Pool-serial discipline: run at most one job per model alias at a time;
  concurrent load on a single alias was observed to starve parallel
  callers on this gateway (hangs with empty-message read timeouts).
- Retry envelope used for these sessions (defaults remain 3/90):
  `GATEWAY_RETRY_ATTEMPTS=8 GATEWAY_CALL_TIMEOUT=150`; the clients
  rotate connections across retries
  (`httpx.Limits(max_keepalive_connections=0)`).
- Recorded, not pursued: `claude-deepseek-v4-flash` deterministically
  hangs on the compiler-test classify payloads (19+ attempts, both
  budgets, connection-rotated retries) while completing the quality
  harness's batched prompts at the same ceiling; no paper number rests
  on that alias for the identity run.
- Prompt-cache billing probe (`gateway_promptcache_probe.json`,
  supplementary I.3): re-send an identical ~800-token system+user
  prefix twice per alias with `cache_control: {type: ephemeral}` blocks
  and inspect the usage fields. The gateway reports plain
  `input_tokens` with `cache_creation_input_tokens =
  cache_read_input_tokens = 0` on both aliases tested — it does not
  surface provider prompt-cache billing, which is why the
  Appendix-G/I.3 provider-cache column stays MODELED while the
  result-cache column's calls and tokens stay gateway-measured.
- Figures: `python scripts/make_figures.py` regenerates all six figures
  (docs/figures/) from the committed results JSONs — every plotted value is
  asserted against its artifact inside the script, and
  scripts/number_regression.py independently re-verifies the emitted
  figures_manifest.json against the same sources. Build order: make_figures
  then build_paper (the build copies docs/figures/ into the LaTeX tree and
  promotes `wide_`-prefixed assets to full-width floats).
- Quota-blocked extensions, recorded so they are not mistaken for
  evidence: attempts to upgrade the committed two-seed reduced-scale
  run to three seeds (full-scale 200-task and reduced-scale 100-task
  variants, glm 5.3 flash) and to add third-family cache-exactness runs
  (`claude-minimax-m3`, `claude-kimi-k2.7-code`) were all rejected by
  the gateway's quota layers (HTTP 429 `AccountQuotaExceeded`; the glm
  pool's window quota exhausted mid-run at full scale, then reported a
  monthly pool exhausted until 2026-11-12 on the reduced-scale retry;
  minimax and kimi pools are monthly, resetting 2026-11-05 and
  2026-11-12). The bench writes no output file on failure, so none of
  these attempts produced a results JSON, and no paper number depends
  on them. The committed multi-seed cache evidence remains the two-seed
  reduced-scale run (`gateway_multiseed_results.json`) and the
  multi-model cache-exactness pair (glm 5.3 flash + doubao
  seed-2.0-code, 200 tasks x 1 seed x 3 skews each).
