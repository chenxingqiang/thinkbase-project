# 审稿意见回复（中文版）

感谢四位审稿人。这一版改的不是"往旧结论上加证据"，而是换了贡献：论文现在**规定并证明**结果复用安全的条件，在记录语料上**测出**未类型化缓存错在哪，**给强制该条件的代价定价**，并把实现**落地**；同时把论文自己的一个数字**向下修正**。以下章节号均指修改稿。

## 主要改动

1. **新增定理 3.7 与推论 3.7.1**（§3.2.4，证明见附录 C.8）：在四条假设下不会发生不安全复用；三族反例说明每条假设都必要。
2. **新增 §5.13 与附录 I.12**：在同一份 2,275 次首轮调用上比较四种缓存策略——盲键命中 807 次、其中 344 次无依据、**240 次造成损害**（61 次写结果被当作已执行二次、179 次在写落库后仍返回旧值）；类型化键在 1,728 次准入调用中命中 466 次、**零**无依据命中；在固定底数上，健全性的代价是 **16.14 个点**的命中率，而不是跨底数比较会得出的 8.5 个点。
3. **类型化缓存已落地**（`agentflow/core/isa/sound_cache.py`），并且**用这个类本身**重放验证：1,728 次调用命中 459 次、零损害，比 harness 少 7 次，差额已解释（121 次因作用域内无租户而被拒绝）。
4. **修正**：化合物吸收率没有通过 task 级 holdout。一半挖掘、另一半测量得到 **10.07%**（229/2,275），样本内为 12.53%。论文现在把 holdout 数字作为"挣到的"比率，样本内数字明确标注为样本内。

## R1：`unsafe` 是由我们自己的键定义的，所以零是分析性的

您说得对，原定义让类型化策略的零变成同义反复。现在"损害"独立于键来判定：一次命中若改变了轨迹的**可观测结果**即为损害，分三类——D1 写响应被重放（61）、D2 在写落库前读到的值（179）、D3 输出是否依赖身份（**实测**而非假定）。正是 D3 把同一批 104 次跨租户命中分成两种读法：`get_product_details`、`list_all_product_types` 对任何调用者返回相同值，这 104 次计为无害；`get_user_details` 不同，那 250 次计为损害。身份依赖按工具逐个测量（`tool_effect_map.json`），不是断言。

**仍未解决的**：这张映射表是我们自己做的。审稿人完全可以主张"即使值公开，跨租户读取本身就是泄露"。我们不作辩解，只把两类分开报，让读者自己定价。

## R2：论文数字可能与工件不符

第 5 节每一个数字都由 `scripts/number_regression.py` 从已提交的 JSON 重算并断言论文原文串，失败即中止，作为构建的最后一步运行。本次修订中它抓出两处错误（过期的用例计数、正文已不存在的短语）。用例计数与 `pytest --collect-only` 对账，"N passed, M skipped" 无法漂移。

可追溯性：每个工件记录语料哈希、模块哈希、随机种子与确切命令；`REPRODUCING.md` 把每条断言映射到模块、测试与 JSON。有一个工件带的是修订前的 `git_rev`，现在用 note 明说，而不是悄悄重生成。

## R3：区间过窄、单位错误

接受并已修正。原数字重采样的是 325 个"来源×模型"格；同一任务内的调用共享轨迹与缓存，因此簇单位应是 **165 个任务实例**。换用该单位后：盲键每千次调用造成 **105.5 次损害 [82.3, 130.1]**，**42.4%** 的实例至少含一次。类型化策略的零改用**精确单侧** Clopper–Pearson 上界（≤1.73/千次准入读），而不是自助区间——零计数的百分位区间是退化的。325 格的数字在修改稿中不再出现。

§5.9 也明确写了：真实网关实验按设计为单种子，仅在有两跑的地方引用两跑结果。

## R4：没有 agent 在环、真实轨迹静态削减 0.0%、你们自己的缓存违反定理、篇幅

- **0.0% 静态削减**是负结果，而且是论文的正面陈述：记录轨迹把观测串成链，因此没有可证明的死步骤，也没有可证明独立的纯函数对。34.2% 属于植入语料，论文现在把它与 0.0% 写在同一句里。
- **我们的缓存确实违反了定理。** `SoundResultCache` 现在把三条假设实现为拒绝规则，论文报的是**已落地类**的重放（459/1,728、零损害），不是 harness 数字。legacy 存储仍是默认，§5.9 第 11 条用计数说明原因：45 个持有缓存的 `execute()` 定义中 0 个能拿到租户，15 个缓存点中 0 个实现 `footprint()`，今天切默认要付 22.7 个点（459 → 67），因为每次写都只能粗粒度失效。**兼容性不是障碍**——设 `AGENTFLOW_CACHE_POLICY=typed`，全量测试通过。
- **没有 agent 在环。** 这条我们不反驳，只限定范围：所有结论都是离线的，摘要里写明了；`docs/review/end_to_end_protocol.md` 是解决它的**预注册**实验设计，含自己的功效分析（200 个任务下约 6 个点）以及"更小的效应将报为不确定"的规则。
- **篇幅**：主文 20 页、第 21 页为空；证明、协议与完整附录 I 表格在 60 页补充材料中。

## 我们希望审稿人重新权衡的一点

论文的价值现在落在一个可被证伪、且我们认为与命中率无关的论断上：**不以租户与失效为条件的复用不是一个性能参数，而是一个正确性缺陷，且它的代价可以测出来——2,275 次调用的语料里，807 次命中中有 240 次造成损害。** 如果这个论断成立，具体的命中率数字不如审计方法重要，而方法正是我们希望被审的部分。
